## Phase 1 — 安全必修（最高優先，實際可利用）

### S1. 照片越權存取 🔴
- **位置**：`internal/handler/photos.go` ServePhoto、`main.go` 路由
- **問題**：只驗路徑穿越 + 檔存在，不驗工單授權；檔名 `wo%d_q%d` 可預測 → 登入員工猜檔名讀其他客戶照片
- **修法**：
  - 路由改為 `/work-orders/{id}/photos/{n}`（工單 id + 序號，不用可預測檔名）
  - 送檔前查：工單存在 + 該照片屬於此工單 + 呼叫者有權看此工單（role/owner 檢查，與 ShowWorkOrder 同級）
  - 檔案對應用 DB 記錄（photo 的 wo_id、seq），不用純檔名推導
- **驗收**：跨工單取照片回 403/404；未授權 role 取照片被擋；測試覆蓋

### S2. 車輛搜尋 XSS 🔴
- **位置**：`internal/handler/vehicles.go` SearchVehiclesAPI:214-233
- **問題**：字串拼接 HTML，車牌/車主/品牌/車型未 escape → 儲存型 XSS
- **修法**：改用 Templ 元件回傳列（符合鐵律）；至少對所有動態欄位 `html.EscapeString`
- **驗收**：車主名稱含 `<script>`/`"><img>` 時不執行；測試注入字串被 escape

### S3. .env 明文憑證 🔴（部分需使用者動作）
- **位置**：`.env:1-18`
- **問題**：明文 LINE secret / access token / 預設密碼
- **修法**：
  - 程式端：確認所有 log 路徑不印憑證（已大致做到，複檢）
  - **使用者動作（助理無法代做）**：到 LINE Developers 輪替 CH secret/token；改預設 owner/counter 密碼
- **驗收**：grep log 輸出無憑證；.env.example 不含真值

## Phase 2 — 後端穩健（高價值）

### B1. 車輛列表 N+1 🟡
- **位置**：`internal/handler/vehicles.go:24-47,177-184`
- **問題**：每列 scanVehicle 查 3 次 lookup + lastMileageOf 1 次；50 筆 >200 查詢
- **修法**：JOIN 或批次查詢一次載入 lookup label 與最新里程
- **驗收**：50 筆頁面查詢數顯著下降；10,000 筆列表 <300ms（加 benchmark）

### B2. 吞錯誤 🟡
- **位置**：`auth.go:214-218,230-252`、`workorders.go:146-160`
- **問題**：忽略 Scan/rows.Err，首頁統計錯誤靜默顯示 0
- **修法**：錯誤明確 log + 人話錯誤頁/partial，不偽裝成空結果
- **驗收**：DB 錯誤不再顯示為 0/空白；log 有錯誤紀錄

### B3. Telegram 長輪詢 graceful shutdown 🟡
- **位置**：`internal/handler/telegram_binding.go:130-176`、`main.go`
- **問題**：停止時沒等 goroutine 退出，可能與 db.Close() 同時碰 DB
- **修法**：cancel context + WaitGroup，shutdown 先停並等待輪詢 goroutine 退出，再 db.Close()
- **驗收**：docker stop 時 log 顯示輪詢先退出再關 DB；無 "database is locked"
