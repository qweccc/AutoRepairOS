# AutoRepairOS 老闆帶客流程（Day-in-the-life）

> 產出：2026-10-07 ｜ 產出者：大C（助理）
> 目的：老闆（櫃檯/管理員）從「客戶到店」到「結帳報表」的完整流程，對照實際模組能力，**標記哪個環節缺功能**。
> 來源：`internal/handler/main.go` 路由盤點 + 舊 Car35 G01~G18 業務流程。

---

## 一、每日開工：儀表板（登入後 `/`）

登入即見總覽儀表板，老闆一眼掌握當日狀態：

| 卡 | 數字 | 意義 |
|---|---|---|
| 進行中工單 | pending + in_progress + waiting_parts | 今日有多少車在修 |
| 進行中 | in_progress | 正在修 |
| 待結帳 | completed（已完工未收款） | **今天該催收款** |
| 客戶數 / 車輛數 | — | 基本資料 |
| 低庫存警報 | stock < 安全存量 | **要補貨的零件** |
| 最近 8 工單 | — | 點可跳工單明細 |

## 二、完整帶客流程

### 步驟 1｜接待：確認/建立客戶（`/customers`）
- 客戶到 → 去「客戶」查是否已有資料。
- 沒有 → **POST 新增客戶**（名稱、電話、發票抬頭）。
- ✅ 有 CRUD，正常。

### 步驟 2｜建車：車輛資料（`/vehicles`）
- 查這台車的資料（車牌、車型、下次保養）。
- 沒有 → **POST 新增車輛**，並關聯到客戶。
- ✅ 有 CRUD + 履歷頁（`/vehicles/{id}`）。

### 步驟 3｜估價（`/work-order_new`）
- 先錄「估價單」：待修項目、預估價格、建議方案。
- 老闆用估價跟客戶談價、決定修不修。
- ✅ 有（GET/POST）。

### 步驟 4｜接車登錄工單（`/work-orders`）
- 客戶同意 → **工單 NEW**，狀態 `pending`。
- 接車資訊：車號、客戶、請款單號、單號、油量、里程、技師。
- ✅ 有 CRUD。

### 步驟 5｜查料/補料（`/inventory` ＋ `/suppliers`）
- 要零件 → 去「庫存」查料號。
- 缺料 → 「供應商」看有沒有（⚠️ **供應商目前只讀**，無法記採購）。
- 下單後 → 工單明細 **加零件**（`/work-orders/{id}/items`）。
- ✅ 庫存有完整 CRUD；供應商缺「記採購」功能。

### 步驟 6｜施工中：更新狀態 ＋ 工時
- 開工 → **更新工單狀態** `pending → in_progress`。
- 技師做什麼 → **新增工時/履歷**（`/work-orders/{id}/worklogs`）。
- ⚠️ 工時只能「新增/刪除」，不能「編輯」。
- ✅ 有。

### 步驟 7｜保險理賠（`/insurance-companies` ＋ `/insurances`）
- 保險車 → 工單標記保險件（`is_insurance`）。
- 保險公司資料 → 「保險公司」CRUD（✅）。
- ⚠️ 「保險投保」目前只讀列表，無法記新投保。
- ✅ 保險公司可用；投保明細缺。

### 步驟 8｜完工交車（`/work-orders`）
- 修完 → **更新狀態** `in_progress → completed`。
- **印收據**（`/work-orders/{id}/receipt`）。
- 照片 → **上傳**（`/work-orders/{id}/photos`）。
- ✅ 都有。

### 步驟 9｜收款沖銷（`/customers` 付款）
- 客戶付款 → **沖銷應收帳款**（現金/信用卡/票額）。
- ⚠️⚠️ **這是大缺口**：系統目前**沒有「應收帳款沖銷」模組**（舊 Car35 G08 有）。
- 影響：老闆無法在系統記「收了多少、還欠多少」。

### 步驟 10｜結帳（`/work-orders`）
- 工單 → `completed → paid`（已結帳）。
- 標記請款/收據狀態。
- ✅ 有。

## 三、老闆每天必看的報表（`/reports`）

登入後報表頁，**保險 / 自費 分開看**：

1. **營收卡**：營收總額 / 保險營收 / 自費營收 / 已結帳工單數
2. **工單狀態分布**：pending/in_progress/waiting_parts/completed/paid（保險、自費各一列）
3. **熱門項目 Top10**：哪幾個零件/項目最常修（保險、自費各一列）
4. **技師績效**：每人工單數、工時、佣金（⚠️ 財務數字僅管理員看）
5. **庫存低水位**：哪些零件要補貨

## 四、⚠️ 流程缺口（老闆會卡的地方）

| 環節 | 現況 | 影響 |
|---|---|---|
| **收款沖銷** | ❌ 無模組、無表 | 無法記收款、無法追蹤應收/已收（**最痛斷點**） |
| **零件進貨登錄** | ❌ 無模組 | 無法記採購成本 |
| **供應商** | ⚠️ 只讀 | 無法新增/記廠商採購 |
| **保險投保** | ⚠️ 只讀 | 無法記新投保 |
| **定檢** | ⚠️ 只讀 | 無法記新定檢 |
| **保養套餐** | ⚠️ 只讀 | 無法記/管理套餐 |
| **支出** | ⚠️ 只讀 | 無法記新支出 |
| **技師佣金** | ⚠️ 只讀 | 無法記新佣金 |
| **工時編輯** | ⚠️ 只能增刪 | 改錯要刪重錄 |

---

## 五、建議優先補哪個

**① 收款沖銷（最痛）**：建 `customer_pay` 表 + `/receivables` 頁 + 扣減工單 `completed→paid`；先手動新增幾筆讓老闆能用，再從 JSON 遷舊收款紀錄。
   - 欄位對照舊 G08 應收帳款沖銷：日期、單號 voucher_no、客戶 customer_id、沖銷單號 apportion_no、車號、結帳日期 due_date、折扣 discount、折讓 allowance、稅稅 tax、現金 cash、信用卡 credit_card、票額 check_amount、票號 check_no、行庫 bank、本期應收 receivable_cur、本期已收 received_cur、備註。
**② 零件進貨登錄**：建表 + 頁（`/supplies` 或 `/inventory/movements`）。  
**③ 供應商 / 投保 / 支出**：補 CRUD → 讓只讀列表頁能用。
**④ 工時編輯**：改錯不用刪重錄。
1. **收款沖銷**（最痛）→ 老闆每天要記錢，沒有就整個財務流程斷掉。
2. **零件進貨登錄** → 缺料時要記採購。
3. **供應商 / 支出 / 投保** 補 CRUD → 讓列表頁能用。
4. **工時編輯** → 改錯不用刪重錄。

## 六、老闆一天節奏（總結）

```
開工 → 看儀表板（待結帳/低庫存）
接客 → 客戶 → 車輛 → 估價 → 工單
查料 → 庫存(+)供應商
施工 → 狀態 + 工時
完工 → 狀態 + 收據 + 照片
收款 → ⚠️ 缺！（沖銷）
報表 → 營收/狀態/熱門/技師/庫存
```

**最痛的斷點 = 收款沖銷**：前面流程都通，但最後「錢」沒地方記。
